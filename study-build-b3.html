Build the casebook from the protocol.

Today data management and EDC (electronic data capture) teams re-key most casebooks from the protocol by hand, then again after every amendment. Study Build creates the casebook from the structured study. It produces CDASH-aligned forms, codelists and edit checks, with the SDTM target for each field that has one. Each build goes through user acceptance testing (UAT) and exports as CDISC ODM 1.3.2 XML.

Study Build

From the approved protocol to a casebook your EDC can load.

Five steps, from the same study.

  1. 01

    Start a build

    Choose how to start, then confirm the EDC target and the CDASH and SDTM versions.

  2. 02

    Standard forms, with SDTM targets

    Pick forms from the CDASH library; each field shows its SDTM target and how it appears in your EDC.

  3. 03

    Place forms on visits

    Mark which forms are collected at Screening, Baseline and each later visit.

  4. 04

    Move through the stages

    Every build moves from Draft to Review, UAT, Approved and Live.

  5. 05

    Validate before export

    Check the Rave file before you download it: folders, forms, fields and codelists.

Into your EDC

Exported as CDISC ODM and as an EDC loader file.

The build exports as CDISC ODM 1.3.2 XML, an open CDISC format for exchanging study designs, with loader files for specific EDCs. The final loader file is produced only from an approved build, and it is checked against the loader's rules first.

If you run one EDC and only need the build, your EDC vendor's tools may be enough. Study Build is for teams that want the casebook built from the protocol, or that run more than one EDC.
