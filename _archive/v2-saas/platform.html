The Platform

Twelve agents. One pipeline. One data model.

Every stage of clinical data — from protocol section authoring through SDTM/ADaM submission — is owned by a cooperating agent. They share the same canonical model, the same RBAC, the same append-only audit trail.

01 · Protocol Authoring

USDM 4.0 protocols, scored ~100/100.

Author M11-aligned protocols section-by-section with an AI co-pilot. Every Code field binds to NCI/CDISC CT. Round-trip exports against CDISC's own reference fixtures pass the CORE rules engine cleanly.

  • 84-section M11 generator covers Title Page through Appendices.
  • CDISC CORE rules run as a pre-export gate — exports block on ERROR-severity findings.
  • Bidirectional consistency: amend a study definition and stale sections auto-flag.
  • USDM 4.0 export + import. SDR-interop-ready for sponsor/CRO handoff.

02 · Study Build

CDASH casebook, Rave or Veeva target.

Read the protocol's SoA, eligibility criteria, and assessments — and generate a CDASH-aligned EDC build. Forms, fields, codelists, edit checks, derivations. Deploy to Medidata Rave (Architect Loader) or Veeva Vault EDC (Casebook Objects) from the same source.

  • Visit schedule + casebook structure derived from protocol.
  • Edit checks classified by criticality and site-query intent.
  • Protocol → CDASH → EDC → SDTM mapping recorded end-to-end.
  • Auto-generated SDS, eCRF spec, and UAT test scenarios.

03 · Data Ingestion

One pipeline. Any EDC. Any vendor.

Rave (ODM.XML or Clinical Views), Veeva Vault (VQL + REST), central labs (SAS7BDAT/XPT/CSV), imaging, RTSM/IxRS, ePRO, devices. Every row carries its source-system OID for idempotent upserts. Schema drift surfaces in real time.

  • Connect → Validate → Normalize → Publish, with quarantine queues.
  • OID preservation across re-extracts. No duplicate rows.
  • Amendment-aware: breaking schema changes pause production until reviewed.
  • Test-load gate stack — Live data flows only after UAT proof.

Syntactic + format checks on every field. Logical edit checks within and across forms for a subject. Cross-source consistency between EDC, RTSM, labs, ePRO. Every finding ships with rule ID, evaluated logic, observed values, and severity.

  • Versioned rule catalog — global, program, study-level overrides.
  • Run on ingest, on demand, or on a schedule.
  • Findings flow directly to Query Management with severity routing.
  • Audit row per finding: who, what, when, which rule version.

05 · Query Management

One lifecycle for every query.

Validation findings, reconciliation discrepancies, coding ambiguities, and manual reviews all flow through one unified Query lifecycle. AI drafts neutral, non-leading query text. Humans approve, edit, or reject — and every step is audited.

  • States: Detected → Draft → Issued → Acknowledged → Answered → Closed.
  • SLA tracking, aging dashboards, bulk operations, escalation rules.
  • Sanitiser strips internal jargon before issuing to sites.
  • DB-lock readiness indicators on every study.

06 · Medical Coding

MedDRA + WHO Drug, AI-first.

Verbatim AEs, medical history, and concomitant medications run through an AI auto-coder that proposes LLT/PT, ATC, or trade-name matches with confidence scores. High-confidence predictions auto-code; the rest flow to a coder workbench for human review.

  • Per-study MedDRA and WHO Drug version pinning.
  • Coder workbench: side-by-side verbatim / suggestion / dictionary browse.
  • Auto-recode triggers when source data changes.
  • Coding-query integration when verbatims are insufficient.

07 · Data Reconciliation

SAE + External, one agent.

One Reconciliation Agent, two sub-agents. SAE: Safety database cases vs EDC AEs/SAEs, matching on subject/date/seriousness/causality. External: vendor data (labs / ECG / imaging / RTSM / ePRO / devices) vs canonical EDC. Discrepancies route to queries or vendor tickets.

  • Shared discrepancy model: type, severity, owner, lifecycle state.
  • Domain-aware matching keys (subject + date + analyte for labs, etc.).
  • AI proposes classifications; humans approve/reject with audited rationale.
  • Run-level + domain-level metrics, exportable reports.

10 · Audit Trail

Append-only. ALCOA+. Always.

Every GxP-relevant action — create, update, delete, approve, sign — is recorded as an immutable audit entry: actor, timestamp with timezone, previous vs new values, reason, study/site/subject context. Tamper-evident storage. Retention at least as long as linked clinical records.

  • One audit model across every module — no module exempt.
  • Search and export by study, subject, user, record type, event type, date range.
  • AI-actor and human-actor distinguishable in every row.
  • Inspection-ready exports: PDF + machine-readable JSON.
